# Clip 1.4.0

Clip 1.4.0 introduces the new Live Share participant mesh. Native participants
can now publish and view at the same time, while a receive-only Web viewer can
join through the same private invitation.

## Participant mesh

- Connect every participant directly to every other participant over WebRTC.
- Let each Native participant share windows, fullscreen video, and one
  independently controlled system-audio track.
- Preserve unrelated connections when someone joins, leaves, or reconnects.
- Support up to four tested room members; two-person sharing remains the
  expected everyday use case.
- End the room cleanly when its creator leaves instead of attempting an
  unreliable distributed leader election.

## Private invitations and friends

- Use one reusable room link for Native Clip and the Web viewer until its owner
  explicitly chooses **New Invite**.
- Keep the high-entropy room secret in the URL fragment so it is not sent to
  the coordination server.
- Add encrypted friend requests, private presence, Access Words, and optional
  join approval.

## Sharing and collaboration

- Add participant-scoped audio controls and application audio exclusions.
- Add low-latency pointers, pings, temporary drawing, source-aware masking, and
  per-window collaboration controls.
- Add Follow, Native, Fit, and fullscreen viewer modes with compact controls.
- Restore source-aware 1× and Retina capture behavior without changing the
  established recording and quality pipeline.

## Web viewer

- Receive every compatible Native participant and shared source in current
  desktop Safari and Chromium browsers.
- Add Native-default rendering, Focus and Row layouts, per-publisher Follow,
  source thumbnails, manual panning, minimaps, fullscreen, audio controls,
  reconnect, and diagnostics.
- Use the exact codec selected by the publisher. Clip does not add a fallback,
  transcode, or second browser encode; an unsupported browser codec is reported
  as **Unsupported Encoding**.
- Keep Web participants receive-only: they cannot publish, administer rooms,
  manage friends, or use collaboration controls.

## Diagnostics and reliability

- Report per-participant routes and per-source codec, resolution, frame rate,
  bitrate, loss, latency, queueing, and quantizer data when available.
- Make codec and stream-setting updates transactional, including rollback and
  retry after partial negotiation or capture failure.
- Bound server rooms, friend-presence storage, payloads, queued traffic, and
  lifetime participant handles.

## Privacy and compatibility

The coordination server sees network addresses, timing, room size, opaque
routing identifiers, and ciphertext sizes. It cannot read the invitation
secret, participant names, SDP/ICE contents, source metadata, collaboration
events, or media. TURN relays encrypted WebRTC packets. The Web viewer origin
can read its page's URL fragment, so self-host the server if you do not trust
the public Web origin.

Live Share 1.4.0 requires the matching
`tomaslejdung/clip-live-share-server:1.4.0` server generation and is not
compatible with pre-1.4 Live Share sessions. Updating or restarting the
memory-only server ends active room signaling. Local recording, Preview,
History, and export remain fully usable without Live Share or any server.

Live Share remains a preview for network, browser, and hardware combinations
that have not completed controlled Internet/TURN and multi-device soak testing.

## Requirements

Clip requires macOS 15 or later on Apple silicon. This build uses the same
stable Apple Development identity as previous updater releases.
